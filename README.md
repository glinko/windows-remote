# Windows Remote

Небольшое приложение для управления своей Windows 11 из Codex. На удалённой
машине работает видимый сервер, на компьютере с Codex — MCP-мост через stdio.
Сервер возвращает вывод PowerShell, ошибки и код завершения. Через PowerShell
можно читать и менять файлы, запускать программы, проверять систему.

## Быстрый запуск

Готовый `.exe` и архив с инструкцией доступны в
[последнем релизе](https://github.com/glinko/windows-remote/releases/latest).

1. Скопируйте `WindowsRemote.exe` на **обе машины**. Python не нужен.
2. На удалённой Windows откройте приложение, вкладку **«1. Удалённая Windows»**.
   Выберите рабочую папку и нажмите **«Запустить»**. Запишите IPv4 и порт,
   нажмите **«Копировать ключ»**. Ключ даёт доступ к выполнению произвольных команд.
3. На компьютере с Codex откройте это же приложение, вкладку
   **«2. Компьютер с Codex»**. Введите `http://IP-МАШИНЫ:8765` и ключ.
   Нажмите **«Проверить соединение»**, затем **«Сохранить и показать настройки Codex»**.
4. Добавьте показанный блок в `%USERPROFILE%\.codex\config.toml`.
   Если секция `[mcp_servers.windows_remote]` уже существует, замените её,
   вместо добавления второй. Перезапустите Codex.
5. В новом диалоге попросите: «Используй windows_remote, проверь удалённую
   машину через remote_info, затем выполни Get-Date».

Для подключения нужны доступный сетевой адрес и разрешённый входящий порт.
Приложение не настраивает маршрутизатор, VPN или брандмауэр автоматически.
HTTP здесь не шифруется: используйте зашифрованный VPN между машинами
(в том числе для подключения через интернет). Не публикуйте этот HTTP-порт
в интернет. Для обычной локальной сети транспорт также передаёт ключ и команды
без шифрования; предпочитайте VPN или TLS-прокси.

Если брандмауэр блокирует соединение, на удалённой Windows разрешите TCP 8765
только для IP компьютера с Codex. Пример в PowerShell от администратора
(**замените IP на адрес вашего компьютера или его VPN-адрес**):

```powershell
New-NetFirewallRule -DisplayName 'Windows Remote - Codex' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8765 -RemoteAddress '192.168.1.50'
```

Удаление этого правила:

```powershell
Remove-NetFirewallRule -DisplayName 'Windows Remote - Codex'
```

## Управление доступом

- Кнопка **«Остановить»** или закрытие окна отключает сервер и прерывает
  активную команду. После повторного запуска приложения нужно снова нажать «Запустить».
- Команды имеют права запустившего приложение пользователя. Запуск от
  администратора даёт командам административные права.
- Рабочая папка — начальная директория, а не песочница. Команды имеют доступ
  ко всем ресурсам, доступным этому пользователю.
- Каждая команда выполняется в новом PowerShell: `cd`, переменные и сессия
  между вызовами не сохраняются. Задавайте `cwd` или абсолютные пути.
- Один вызов длится до 120 секунд (по умолчанию 30). Вывод ограничен
  64 КиБ отдельно для stdout и stderr. Флаг `truncated` сообщает об обрезке.
- Выполняется одна команда за раз. При таймауте завершается дерево процесса
  PowerShell. Программы, запущенные отдельно через `Start-Process`, могут
  продолжить работу после завершения команды и отключения сервера.
- Нет управления мышью, экраном, RDP, автозапуска или установки Windows-службы.
  Это приложение для команд, работающее пока открыто его окно.

Настройки и ключи хранятся в `%LOCALAPPDATA%\WindowsRemote\server.json` и
`bridge.json` в открытом виде. Не пересылайте эти файлы и не добавляйте их в Git.
Чтобы сменить ключ, остановите сервер, замените поле на новый случайный ключ
из не менее 32 ASCII-символов, запустите сервер и обновите настройки моста.
Журнал `audit.jsonl` содержит время, PID, хеш команды и результат завершения;
текст команд, ключи и вывод туда не записываются. При 5 МБ журнал ротируется.

## Запуск из исходников

Нужен Python 3.11+ с Tkinter. Сторонние библиотеки для работы не нужны.

```powershell
python remote_agent.py
python remote_agent.py --check --config "$env:LOCALAPPDATA\WindowsRemote\bridge.json"
```

MCP-мост запускается самим Codex:

```powershell
python remote_agent.py --mcp --config "$env:LOCALAPPDATA\WindowsRemote\bridge.json"
```

Для `.exe` те же аргументы. Программа при двойном щелчке показывает окно и
консоль; консоль оставлена для совместимости исполняемого файла со stdio MCP.
Вкладка подключения генерирует блок с абсолютным путём к используемому
`.exe` или Python. После перемещения файла обновите этот блок.

## Проверка и сборка

```powershell
python -m unittest -v test_remote_agent.py
python smoke_gui.py
python -m venv .build-env
.\.build-env\Scripts\python.exe -m pip install pyinstaller
.\.build-env\Scripts\python.exe -m PyInstaller --clean --noconfirm --onefile --name WindowsRemote remote_agent.py
python smoke_exe.py
```

Результат: `dist\WindowsRemote.exe`. Это неподписанная сборка, поэтому Windows
может показать предупреждение SmartScreen. Из исходников можно собрать её
самостоятельно. Никакой автоматической регистрации в Codex не выполняется.

Настройка stdio MCP соответствует [официальной документации OpenAI](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
Мост реализует небольшой набор [MCP 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle):
initialize, ping, tools/list и tools/call, с JSON-сообщениями по строкам stdio.
HTTP-сервер на удалённой машине — внутренний API, его адрес нельзя указывать
в Codex как адрес Streamable HTTP MCP: подключение идёт через локальный мост.
